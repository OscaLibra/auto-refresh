# 使用手册

> 面向使用者。安装方式：`chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 → 选本目录。

## 一、怎么临时关掉（建议先看这段）

有四种关法，按「影响范围从小到大」排列：

1. **只暂停当前标签页**：点工具栏图标 → 「暂停」。该标签不再刷新，其它标签不受影响。恢复后重新计时。
2. **停用某条网址规则**：设置页 → 对应规则 → 「停用」。该网址所有标签都不再计时。
3. **全局关闭**：设置页右上角「全局启用」开关，或弹窗里关掉。所有页面停止计时。
4. **彻底移除**：`chrome://extensions` → 移除扩展。规则与权限一并清除。

> 暂停和关闭都**不会**弹任何提示，所以如果发现「怎么不刷新了」，先看图标角标：显示 `||` 表示已暂停。

## 二、为什么偶尔会晚一分钟

这是浏览器的行为，不是插件 bug：

- 页面切到后台超过 5 分钟后，浏览器会把页面里的定时器降频到**每分钟只跑 1 次**（省电）。
- 所以插件只能保证「在阈值之后 1 分钟内刷新」，做不到秒级。
- 另外系统休眠 / 合盖唤醒后，插件会**故意等 2 秒**才刷新，避免你刚睁开眼页面就闪一下。

如果你的场景对时间很敏感，把阈值再往前提 1–2 分钟即可。

## 三、阈值该设多少

**阈值 = 那个系统实测的登录超时时间 − 2 分钟。**

例如实测 15 分钟不动就掉登录，就设 13 分钟。留 2 分钟是因为：后台降频最多延迟 60 秒、刷新本身要走一趟网络、服务器时钟可能有偏差。

怎么实测：登录后不动，DevTools → Network，盯着第一个 `401` / 跳登录页的时间；或者每 2 分钟点一次页面内的链接，记录「哪一分钟点下去跳登录页了」。测 3 次取最小值。
> 注意反向代理层（Nginx / F5 等）常常有自己的空闲超时，比应用层更短，所以要以**实测最短的那个**为准。

## 四、刷新会丢东西吗

会。刷新等价于按了一次 F5：

- 输入框里没提交的内容会丢；页面上的筛选条件、展开状态通常也会重置。
- 滚动位置会被恢复（默认开启），但表单内容不会。

因此：

- **正在填长表单、写长文档的页面，改用「仅保活，页面不动」模式。** 它只发一次同源请求续期，页面完全不动。
- 或者在规则上设置「刷新前提示 15 秒」，到点前会弹一个倒计时浮窗，点「稍后，重新计时」就能再撑一轮。
- 如果页面自己弹了「确定要离开吗？」的确认框，插件会识别为「被拦截」，**不会连环骚扰你**，并在 15 分钟后再试（可在设置里关掉这个提示）。

## 五、常见问题

**Q：完全不刷新。**
按顺序查：① 图标角标有没有数字（没有 = 当前页没被监控，网址不在规则里）→ ② 设置页规则上是否显示「需重新授权」（权限被浏览器重置了，点一下重新授权）→ ③ 全局开关是否打开 → ④ 网址是否写得太具体（`/app/list` 只能匹配那一页，建议用 `/app`）。

**Q：刷新太频繁。**
你的阈值比实际会话超时短太多。也可能是打开了「把页面滚动也算作有操作」——日志流、轮播图会自动滚动，反而让计时一直在重置，那种页面应该**关掉**这个选项。

**Q：刷新后要重新登录。**
说明阈值设得比真实超时大，插件醒来时会话已经没了。按第三节实测后调小。

**Q：某个系统突然频繁弹确认框。**
那个站点新加了「离开确认」，把该规则改成「仅保活」模式即可。

**Q：能监控内网的 IP 地址吗？**
可以，但要写成 `http://10.1.2.3/*` 这种形式；match pattern 不支持端口号，带端口会被自动忽略。

**Q：换电脑要重新配吗？**
要。规则只存本机，且刻意不做跨设备同步（内网地址不该同步到云端）。

## 六、它到底看了什么

- 只看「你最后一次动鼠标/敲键盘是什么时候」，**不读你做了什么**。
- 不读 Cookie、不读表单、不读页面文字、不看剪贴板。
- 不向任何服务器发数据；「仅保活」模式发的请求是你当前页面自己的地址。
- 明细数据只存在本机内存里，浏览器一关就没了。
- **不要拿它做考勤或在岗监控**，这超出了它的设计目的，也不符合合规要求。真需要考勤请走独立的人事系统并依法告知员工。

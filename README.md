# 空闲自动刷新（会话保活）

一个 Chrome / Edge 浏览器扩展：**在指定的后台页面上盯着「你多久没操作」，到点自动刷新一次页面**，
防止长时间不动被服务端的会话超时踢回登录页、丢掉填了一半的表单。

```
你在 OA 后台开着工单页 → 去开会 20 分钟 → 回来点「保存」→ 登录页 ❌
装了本插件       → 每 10 分钟没有操作就自动刷一次 → 会话一直有效 → 保存成功 ✅
```

- 目标平台：Chrome / Edge（Manifest V3，Chrome 120+）
- 当前版本：1.0.3 ｜ 更新记录见 [CHANGELOG.md](CHANGELOG.md)
- 下载安装：[Releases](https://github.com/OscaLibra/auto-refresh/releases/latest)

---

## 一、它能做什么

| 能力 | 说明 |
| --- | --- |
| **按网址配置规则** | 只在你指定的页面生效，可以配多条；不匹配的页面零开销、零注入 |
| **两种到点动作** | 「刷新页面」（默认，续期最可靠）或「仅保活」（发一次同源请求，页面不动、不打断输入） |
| **刷新前提示** | 可选：到点前弹一个倒计时浮层，点「稍后」可以再撑一轮，不怕正在填表 |
| **随时暂停** | 弹窗里一键暂停当前标签的计时，恢复时重新计满一轮 |
| **立即刷新** | 弹窗里手动触发一次，不用等倒计时 |
| **剩余时间可见** | 工具栏角标显示剩余分钟；弹窗里是精确到秒的倒计时 |
| **iframe 也算操作** | 主操作区在 iframe 里的后台系统（跨域也支持），在里面点一下同样算「有操作」 |
| **刷新后回到原位置** | 默认记住滚动位置，刷新完自动滚回去，长列表页不用重新找 |
| **最小化 / 后台照常执行** | 窗口最小化、标签在后台、渲染进程被浏览器冻结，到点照样刷新（最迟到点后约 40 秒） |
| **权限最小化** | 安装时**不弹任何权限提示**，只在添加某个网址时申请那一个域名的访问权 |

### 它不是什么

- **不是考勤 / 在岗监控工具**，也请不要这么用（见文末「隐私与合规」）。
- **救不回已经过期的会话**：它只在会话还有效时续期。真过期了刷新就是正常跳登录页。
- **不模拟点击、不自动登录、不绕过二次认证**。

## 二、安装

### 方式一：下载安装包（推荐）

1. 打开 [最新 Release](https://github.com/OscaLibra/auto-refresh/releases/latest)，下载 `auto-refresh-x.y.z.zip` 并解压到一个**不会被删除的固定目录**（扩展运行期间不能删）。
2. 地址栏输入 `chrome://extensions`（Edge 是 `edge://extensions`）→ 打开右上角「开发者模式」。
3. 点「加载已解压的扩展程序」→ 选中解压出来**含 `manifest.json` 的那一层目录**。
4. 建议把扩展图标固定到工具栏（拼图图标 → 图钉），方便看剩余时间和暂停。

> 安装时不会出现「读取和更改您在所有网站上的数据」这类提示——本扩展只在添加规则时按域名申请权限。

### 方式二：从源码加载

```bash
git clone https://github.com/OscaLibra/auto-refresh.git
# 然后同「方式一」第 2~3 步，选中 auto-refresh/ 目录
```

## 三、快速上手（3 步）

1. **打开设置页**：`chrome://extensions` → 本扩展卡片 → 「扩展程序选项」。
2. **添加一条规则**：填网址 → 设空闲阈值（默认 10 分钟）→ 选到点动作 → 保存。
   网址只填 `oa.example.com/app` 也可以，会自动补全成 `https://oa.example.com/app*`。
3. **授权并验证**：保存时浏览器会弹「允许访问 oa.example.com」→ 点「允许」；
   打开那个页面，工具栏角标出现数字（剩余分钟）就说明生效了。

> 想快速验证：把阈值临时设成 **1 分钟**，静置 1 分钟看它是否刷新，再改回正式值。

## 四、使用说明

### 4.1 规则怎么填

| 你填的 | 实际生效范围 | 适用场景 |
| --- | --- | --- |
| `oa.example.com` | `https://oa.example.com/*` | 整个站点 |
| `oa.example.com/app` | `https://oa.example.com/app*` | 该路径及子路径（推荐，范围可控） |
| `https://*.example.com/app*` | 原样使用 | 多子域 |

- 支持 `http` / `https`；不写协议时默认 `https`。
- **不支持端口号**：Chrome 的匹配规则本身不支持端口，`https://host:8443/app` 会被剥成 `https://host/app*`（覆盖该域名所有端口）。
- 建议**写到业务路径前缀**（如 `/app`）而不是具体某一页（如 `/app/list?id=3`），否则换一页就不生效。

### 4.2 到点动作怎么选

| | 刷新页面（reload） | 仅保活（ping） |
| --- | --- | --- |
| 行为 | 真的重新加载页面 | 对当前地址发一次同源请求，页面**完全不动** |
| 续期可靠性 | 最可靠（等价于你手动按 F5） | 多数系统有效；少数系统只在渲染页面的 GET 上续期 |
| 副作用 | 未保存的输入会丢（可开「刷新前提示」兜底） | 无感，不打断 |
| 推荐 | 展示型页面、监控大屏、只读后台 | 正在长时间填表、页面状态复杂、怕丢现场 |

「仅保活」失败时会按设置降级为刷新（可在规则里关闭降级）；到点动作随时可在规则里改。

### 4.3 刷新前提示（防丢表单）

给规则设置「刷新前提示 N 秒」（0 = 静默刷新，最大 120 秒）：

- 到点前 N 秒，页面右下角出现倒计时浮层；
- 点「稍后，重新计时」→ 计时归零重来一轮；
- 浮层用 Shadow DOM 隔离，不会被站点样式弄变形，站点脚本也改不了它。

### 4.4 弹窗面板（点工具栏图标）

- **剩余时间**：精确到秒，每 5 秒与后台校准一次；
- **暂停 / 恢复**：暂停只对当前标签生效，页面刷新后仍保持；
- **立即刷新**：手动触发一次（等价于按一次 F5）；
- **设置与规则**、**导出诊断**（一键复制 JSON，排查问题时发给管理员）。

### 4.5 角标含义

| 角标 | 含义 |
| --- | --- |
| `7` | 还剩约 7 分钟 |
| `<1` | 不到 1 分钟（红色） |
| `||` | 已暂停（黄色） |
| 无 | 当前页不在任何规则里，没有在计时 |

### 4.6 全局设置项

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 全局开关 | 开 | 关掉后所有规则暂停生效（规则保留） |
| 默认空闲阈值 | 10 分钟 | 新规则的默认值，单条规则可覆盖（1–180 分钟） |
| 默认到点动作 | 刷新页面 | 同上 |
| 默认提示时长 | 0 秒 | 0 = 静默刷新 |
| **把页面滚动也算「有操作」** | 关 | 日志流 / 轮播 / 无限加载页面**别开**，否则滚动事件会让它永不刷新 |
| **把鼠标移动也算「有操作」** | 关 | 默认只有点击 / 键盘 / 滚轮 / 触摸才算操作；开启后轻微挪鼠标也会重置倒计时 |
| 刷新被页面拦截时提示我 | 开 | 页面有「确定离开吗」时提示一次，并自动延后重试 |
| 输出调试日志 | 关 | 排查问题时打开，控制台会出现 `[AR]` 日志 |

### 4.7 阈值设多少合适

**按实测值减 2 分钟设，不要照抄默认 10 分钟。** 反向代理层的空闲超时常常比应用层更短。

实测方法：登录后静置，记下多久被踢回登录页（看 Network 里第一个 302/401 的时间），
把阈值设为「实测分钟数 − 2」。拿不准就先设 8 分钟。

### 4.8 不同状态下的行为（延迟预期）

| 页面状态 | 谁在执行 | 到点后多久刷新 |
| --- | --- | --- |
| 前台可见 | 页面自己（1 秒精度） | 约 1–2 秒内 |
| 后台标签 / 窗口被遮挡 | 页面自己（定时器被降频） | 最多约 60 秒 |
| **浏览器最小化 / 页面被冻结** | 后台服务直接刷新 | **最迟约 40 秒** |
| 标签被浏览器休眠（discard） | 后台服务直接刷新 | 需先唤醒页面，最迟约 40 秒 |

- 最小化、切到别的窗口、把窗口挪到屏幕外，**都不会重置倒计时**——只有真实操作才会。
- 鼠标移动 / 悬浮、页面自己滚动，**默认都不算操作**（可在设置里开）。
- 页面有「离开确认」拦住刷新时，会识别为「被拦截」并延后一轮，不会连环弹框。

## 五、常见问题

**Q：装了但完全不刷新。**
按顺序查：① 角标有没有数字（没有 = 当前页不在规则里，检查网址写法）→ ② 规则上是否显示「需重新授权」（浏览器重置了权限，点一下重新授权）→ ③ 全局开关是否打开 → ④ 网址是否写得太具体（`/app/list` 只匹配那一页，建议用 `/app`）。

**Q：刷新太频繁。**
阈值比实际会话超时短太多；或者开了「把页面滚动也算作有操作」——自动滚动的页面会让计时反复重置，应该关掉。

**Q：刷新后要重新登录。**
说明阈值设得比真实超时大，刷新时会话已经没了。按 4.7 实测后调小。

**Q：某个系统刷新时频繁弹「确定要离开吗」。**
那个站点有离开确认。把该规则改成「仅保活」模式，或给规则设置「刷新前提示」手动接管。

**Q：最小化 / 切到后台还会刷新吗？**
会。最小化时页面会被浏览器降速甚至冻结，所以由后台服务亲自兜底：刷新模式下最迟到点后约 40 秒一定执行。

**Q：鼠标在页面上悬停、轻微移动，会重置倒计时吗？**
不会（1.0.2 起）。只有点击、键盘、滚轮、触摸才算操作。

**Q：能监控内网 IP 吗？**
可以，写成 `http://10.1.2.3/*` 这种形式。

**Q：换电脑要重新配吗？**
要。规则只存本机，刻意不做跨设备同步（内网地址不该同步到云端）。

## 六、隐私与合规

- **只看「你最后一次动鼠标 / 敲键盘是什么时候」**，不读你做了什么。
- 不读 Cookie、不读表单内容、不读剪贴板、不接触任何账号凭据。
- 不向任何第三方服务器发数据；「仅保活」只请求你当前页面自己的地址；没有埋点、没有统计 SDK、没有远程代码。
- 活动时间戳只存在本机浏览器会话里，浏览器关闭即清空，不上传、不落盘、不聚合。
- **请勿用于考勤或在岗监控**——这超出它的设计目的，也可能违反当地法规。需要考勤请走独立的人事系统并依法告知员工。

---

## 七、它做不了什么

- **救不回已过期的会话**（见上）。
- **不保证秒级准时**：后台最坏约 60 秒，最小化/冻结场景约 40 秒（后台兜底）。
- **不支持带端口的规则**（Chrome match pattern 限制）。
- **不监听 SPA 的 `pushState`**：站内路由切换后由 `tabs.onUpdated` + 重匹配兜底，最多 90 秒内按新地址判定。
- **不跨设备同步规则**。

## 八、开发者

工程与自检脚本（Node 18+，生成图标需要 Python 3）：

```bash
node tools/verify.mjs        # 120 项：manifest 权限红线、content 无 ESM、常量一致性、pattern 单测
node tools/simulate.mjs      # 58 项：content 端运行时冒烟（vm + DOM 桩）
node tools/simulate-sw.mjs   # 78 项：service worker 集成（内存版 chrome.* 桩）
node tools/pack.mjs          # 产出 dist/auto-refresh-{version}.zip
```

架构要点（评审常问）：计时主责在 **content script**（前台 1 秒精度），service worker 只做
30 秒 `alarms` 巡检兜底；content 脚本用动态注册（`chrome.scripting.registerContentScripts`），
manifest 里没有 `content_scripts` 段，所以安装时零权限提示；权限按**域名**申请、脚本按**路径**注册。

目录结构、调试上下文（content 日志要切到扩展上下文才能看到）与设计取舍见
[docs/运维手册.md](docs/运维手册.md)；手工验收用例见 [docs/验收清单.md](docs/验收清单.md)；
面向使用者的完整说明见 [docs/用户手册.md](docs/用户手册.md)。
